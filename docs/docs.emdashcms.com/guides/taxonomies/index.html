Taxonomies

A taxonomy is a named classification applied to one or more collections. EmDash starts with the hierarchical category taxonomy and the flat tag taxonomy for posts. A site can also define taxonomies such as genre, topic, or difficulty.

Terms belong to a taxonomy. A category such as “Guides” can have child categories, while tags and other flat taxonomies have one level.

Manage terms

Section titled “Manage terms”

Open a taxonomy from Taxonomies in the EmDash admin.

  1. Click Add Category, Add Tag, or the equivalent action for the current taxonomy.

  2. Enter the label and slug. For a hierarchical taxonomy, choose a parent when the term belongs below another term.

  3. Add an optional description, then create the term.

  4. Use the move controls in the term list to set the order within the current parent group.

Editors assign terms from the taxonomy panels in a content entry. The taxonomy definition controls which collections show each panel.

Deleting a term removes its assignments from content. It does not delete the content entries.

Add one term to several posts

Section titled “Add one term to several posts”

Editors can select posts in a collection list and click Add followed by the taxonomy’s singular name (for example, Add tag), or open a taxonomy’s page and click Add to posts to paste public post URLs (one per line, up to 50). When more than one taxonomy applies to the collection, the list shows Add term, and the dialog asks which taxonomy to use. Choose an existing term or create one in the dialog, then click Review posts. Check every matched title and language, then click the button showing how many posts will be updated. Links that do not exactly match a published post on this site are flagged rather than guessed. Only entries in collections that use the chosen taxonomy can be matched.

Adding the term takes effect immediately, even when a post has other unpublished draft edits; it does not publish those edits. Existing terms remain in place, and posts that already have the term are skipped. The result list shows which posts were updated, skipped, or could not be updated; use Retry failures for write failures. URL matching uses the site’s configured public origin and collection URL patterns, including date and language paths.

Add a custom taxonomy

Section titled “Add a custom taxonomy”

Create a taxonomy when an existing collection needs a separate classification.

  1. Open Taxonomies and click New Taxonomy.

  2. Enter a label and a stable name. Names start with a lowercase letter and contain only lowercase letters, numbers, and underscores.

  3. Enable Hierarchical if terms need parent and child relationships.

  4. Select every collection that can use the taxonomy, then click Create Taxonomy.

  5. Add the initial terms and assign them to content.

Templates query the stable name. Changing a display label does not require a template change.

Delete a taxonomy

Section titled “Delete a taxonomy”

Open the taxonomy in the admin, then choose Delete taxonomy from the actions menu in the page header and confirm. The action requires the taxonomies:manage permission, which editors and administrators hold.

Deleting a taxonomy deletes its terms in every language and removes those terms from the content filed under them. The content entries themselves are kept.

Caution

Deleting a taxonomy cannot be undone. Templates that query the deleted name keep rendering but show nothing: getTaxonomyTerms() returns an empty array, and a where filter on the name returns no entries. Update those queries and the archive pages that depend on them.

Translate taxonomies and terms

Section titled “Translate taxonomies and terms”

Taxonomy definitions and terms have one row per locale. EmDash records which rows are translations of the same taxonomy or term. Content assignments use that shared identity, so an assignment made in one locale resolves to the translated term in another locale when one exists.

A taxonomy definition splits its fields between the taxonomy and each locale:

Field Belongs to Effect
name Taxonomy Fixed after creation. Every locale’s definition uses the same name.
hierarchical, collections Taxonomy The same in every locale. Changing either through any locale changes it for all locales.
label, labelSingular Locale Each locale’s definition has its own.

A definition created for a name that already exists in another locale joins that taxonomy, with or without translationOf, and takes its hierarchical and collections. Creating it with different values fails; change them with an update. A locale without its own definition still lists the taxonomy’s terms and shows the label of the first locale on its fallback chain that has one, else the default locale’s label, else the label of the locale with the lowest locale code.

Use the locale switcher on a taxonomy page to manage terms in each configured locale. Open a term’s edit dialog and use its Translations panel to add or open another locale. A translated term can use a different slug and label.

A term’s parent and position are shared by every locale. A translation created without a parent takes its term’s parent and position. Creating a translation under a different parent, or changing the parent through any locale, moves the term in every locale.

The query helpers use an explicit locale when supplied. Otherwise they use the current request locale, then the configured default. Single-term lookups follow the configured fallback chain when the requested translation is absent.

Tip

Keep taxonomy names stable across locales. Translate the definition label, term labels, and term slugs; templates continue to query the same name, such as category.

See Internationalization for locale routing and fallback configuration and Working with Content for editing entries. The runtime API reference documents taxonomy query helpers. For programmatic changes, authenticate with a Bearer token and add X-EmDash-Request: 1 to every state-changing request. See the taxonomy endpoints for request bodies and responses.
