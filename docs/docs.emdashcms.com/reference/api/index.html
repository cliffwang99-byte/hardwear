JavaScript API Reference

This page covers the public API used by Astro pages, layouts, and components to read and present an EmDash site. It does not inventory every export from the emdash package root: database repositories, API handlers, migration utilities, plugin-authoring APIs, and other server internals have separate references or are intended for framework integration code.

The site-template API contract in this reference lists every runtime export imported from emdash by EmDash’s maintained site templates. Type-only imports such as MediaValue belong to the relevant data-model documentation. Related functions are documented in the same sections when they help a site author, but the page does not cover unrelated root exports.

Site-template API contract

Section titled “Site-template API contract”

The maintained templates use these runtime exports:

Export Used for
decodeSlug Decoding a dynamic route parameter before lookup
getContentSeo Reading an entry’s SEO panel values without template fallbacks
getEditMeta Detecting an empty field that still renders its inline editor in edit mode
getEmDashCollection Reading and filtering entries in a collection
getEmDashEntry Reading one entry by ID or slug
getMenuWithCacheHint Rendering a navigation menu with cache invalidation
getSeoMeta Resolving an entry’s SEO panel values and template fallbacks
getSiteSettings Reading public site identity and other global settings
getSiteSettingsWithCacheHint Reading global settings with cache invalidation
getTaxonomyTermsWithCacheHint Rendering taxonomy filters with cache invalidation
getTermsForEntries Batch-loading one taxonomy for a list of entries
sanitizeHref Rejecting unsafe URL schemes before rendering stored links
search Searching published content across collections
SearchUnavailableError Showing a search-unavailable message when SQLite lacks FTS5

Content types

Section titled “Content types”

ContentEntry

Section titled “ContentEntry”

Query functions return entries in the following shape:

The edit proxy provides visual editing annotations. Spread it onto elements to enable inline editing: {...entry.edit.title}. Outside edit mode, it produces no output.

The data object contains all content fields plus system fields:

  • id - Unique identifier
  • slug - URL-friendly identifier
  • status - “draft” | “published” | “archived”
  • createdAt - Creation time as a Date
  • updatedAt - Last update time as a Date
  • publishedAt - Publication time as a Date, or null; retained when content is unpublished
  • Plus all custom fields defined in your collection schema

ReferencePage

Section titled “ReferencePage”

entry.references holds one page per reference field that getEmDashEntry was asked for, keyed by field slug:

Each entry is mapped the way a directly loaded entry is, with one exception: bylines and taxonomy terms are not hydrated, so data.bylines and data.terms are absent.

URL helpers

Section titled “URL helpers”

decodeSlug() and slugify()

Section titled “decodeSlug() and slugify()”

Use decodeSlug() on a dynamic route parameter before passing it to a content query. It returns undefined for a missing parameter or a malformed percent-encoded string, and otherwise returns the decoded slug:

slugify(value) converts text to a lowercase, hyphen-separated slug. Use it when a template needs to construct a slug from a label; stored entry slugs already come from EmDash.

sanitizeHref() and isSafeHref()

Section titled “sanitizeHref() and isSafeHref()”

These helpers accept http:, https:, mailto:, tel:, site-relative paths, and fragments. They reject script-capable schemes, protocol-relative URLs, backslash-prefixed forms that browsers resolve to another site, and control characters. isSafeHref(value) returns a boolean. sanitizeHref(value) returns the original safe URL or "#" when the value is empty or unsafe.

Content converters

Section titled “Content converters”

Convert between Portable Text and ProseMirror formats:

The ProseMirror document uses EmDash’s own nodes for built-in blocks, such as image, table, iframeBlock and videoBlock. A TipTap editor that loads it needs those nodes in its schema, or it can’t load documents that use them. A videoBlock node has the attributes src, mediaId, provider, caption, width and height.

Site settings

Section titled “Site settings”

Read site-wide settings with getSiteSettings and getSiteSetting:

Settings are read-only from the runtime API. Use the admin API to update them.

getSiteSettings() returns a partial object because unset keys are omitted. Media settings such as the site logo and favicon are resolved to media-reference objects before the function returns.

getSiteSettingsWithCacheHint() returns { data, cacheHint }. Pass the hint to Astro.cache.set() when an Astro route cache should be invalidated after site settings change.

SEO

Section titled “SEO”

Resolve the SEO panel values and content fallbacks for a page with getSeoMeta():

It returns the resolved title, description, Open Graph values, canonical URL, and robots value. getContentSeo(content) returns the raw SEO object without applying template fallbacks.

For translated content, getHreflangAlternates(collection, entryId, { siteUrl? }) returns published, routable locale variants as { hreflang, href } objects and adds an x-default entry. It returns an empty array when internationalization is disabled, the current entry is marked noindex, or no absolute site URL is available.

Comments

Section titled “Comments”

Fetch approved comments and their count for an entry:

threaded nests replies below their parent. The default sort is "oldest"; "best" ranks top-level comments by reactions and enables reaction counts automatically. Server-rendered comment queries return at most 500 approved comments; use the REST API when a client needs pagination.

Translate the comment components

Section titled “Translate the comment components”

The Comments and CommentForm components from emdash/ui/comments render English text by default. Pass a labels object to replace any of it. Keys you leave out, or set to undefined, keep their English default:

Comments accepts heading, member, and like. heading receives the number of approved comments, so it can return a separate text for zero comments.

CommentForm accepts name, email, comment, submit, submitting, published, pending, error, and networkError. The form shows published when the comment is approved immediately and pending when it waits for moderation. Without error, the form shows the server’s English error message.

Comments formats comment dates in the page locale (Astro.currentLocale) and falls back to en-US. Astro sets Astro.currentLocale only when the i18n configuration is enabled. Without it, or to use a different format, pass a BCP 47 locale tag such as locale="de-CH".

Menus

Section titled “Menus”

Fetch navigation menus and iterate their items, including nested children:

getMenu(name, { locale? }) follows the configured locale fallback chain. getMenus({ locale? }) lists menu summaries for the resolved request or configured locale; without internationalization it lists every locale. getMenuWithCacheHint() returns { data, cacheHint } for routes using Astro’s cache.

Bylines

Section titled “Bylines”

Fetch an author profile by ID or slug, or list entries credited to a byline:

getByline(id) returns one profile or null. The slug lookup accepts an optional locale and follows the locale fallback chain. Content queries already hydrate an entry’s ordered credits into entry.data.bylines; use these standalone helpers for author pages and byline archives.

Taxonomies

Section titled “Taxonomies”

Fetch taxonomy terms, a single term, an entry’s terms, or entries by term:

getTaxonomyDefs({ locale? }) lists one definition per taxonomy, and getTaxonomyDef(name, { locale? }) returns one definition, or null when no locale defines the taxonomy. Both resolve a taxonomy in every locale; Translate taxonomies and terms explains which locale’s label they use. Term lookups follow the configured fallback chain.

getTaxonomyTerms(name, { locale?, includeCounts? }) returns a tree for hierarchical taxonomies and includes visible-entry counts by default. Pass includeCounts: false when the template does not render counts. Content queries also hydrate assigned terms into each entry’s data.terms; use getEntryTerms() when you only have a collection name and entry ID.

For archive pages that render terms beside many entries, batch the lookup instead of calling getEntryTerms() in a loop:

getTermsForEntries() returns a map from entry ID to the requested taxonomy’s terms. getAllTermsForEntries() returns a map from entry ID to terms grouped by taxonomy name. getTaxonomyTermsWithCacheHint() returns { data, cacheHint } for an Astro-cached route.

Widget areas

Section titled “Widget areas”

Fetch widget areas and the widgets they contain:

getWidgetAreaWithCacheHint(name) returns { data, cacheHint } for routes using Astro’s cache. Widget areas and their widgets are ordered by their configured sort order.

Sections

Section titled “Sections”

Fetch sections and filter them:

getSections(options?) returns { items: Section[]; nextCursor?: string }. Options are source ("theme" | "user" | "import"), search, limit (default 50, max 100), and cursor.

Search

Section titled “Search”

SQLite search requires FTS5. A non-empty search throws SearchUnavailableError (exported from emdash, with code SEARCH_UNAVAILABLE) when the SQLite build lacks FTS5, even if no collections have search enabled. A server-rendered page that does not catch this error returns an error response; catch it at the page boundary to show a search-unavailable message. See the Node.js deployment prerequisites for a capability check and recovery steps.

Run a global search across collections. Results include highlighted snippets:

With scope: "title" the query matches only each collection’s title field instead of the full indexed text – useful for pickers and autocomplete where body-text matches would surprise. Collections whose title field is not indexed for search return no results under this scope.

Error handling

Section titled “Error handling”

Content queries return operational errors in their result instead of throwing. A missing entry is not an operational error: entry is null and error remains undefined.

Helpers without a result envelope can throw when their input is invalid or a database operation fails. Handle those errors at the route boundary when the page can provide a useful fallback. The repository and handler error classes used by lower-level server integrations are outside this site-template API.
